# 拾光 SnapSaga · P0 落地计划

> 依据《拾光SnapSaga-旅拍创作App-产品设计稿.html》v0.1 细化。
> 范围：P0 MVP（拍得对 + 修得快）8 周完整计划，含 P1 风险前置项。
> 团队假设：Flutter ×2 + 后端/AI ×1 + 设计 ×0.5 + PM/合规 ×0.5。最小配置（2 名全栈）周期 ×1.35，见 §6。

## 0. 开工前必须锁定的 5 个技术决策

| # | 决策项 | 结论 | 说明 |
|---|--------|------|------|
| D1 | 生图调用形态 | **客户端不直连 gpt-image-2**，经自建轻量网关代理 | API key 永不进客户端；网关统一做鉴权、配额、审核、计费、Provider 切换。设计稿的「Provider 抽象层」落地为网关内的路由表 |
| D2 | 网关部署 | 国内云 + 海外出口代理，双路由 | gpt-image-2 可达性/时延有区域差异；路由表预置一个**已备案的国内生图模型**作为降级 Provider（合规+可达双保险） |
| D3 | 本地数据库 | **Drift**（主），ObjectBox（备） | 原定的 Isar 维护活跃度风险高，P0 就换，避免中期迁移 |
| D4 | 端侧 ML | ML Kit on-device 系列捆绑打包 | 不依赖 GMS 服务框架，国内 ROM 可用；确认后锁定包体积预算（≤ 25MB 增量） |
| D5 | 目标市场与上架路径 | 国内安卓商店 + iOS（中国区） | 触发 E 组合规任务：**生成式 AI/深度合成算法备案**为上架前置项（周期 4–8 周），W1 启动，不阻塞内测 |

另有两处对设计稿的**修正**（随本计划生效）：
1. 主题包命名规避 IP 词：~~宫崎骏夏天~~ → **「夏日手绘动画风」**；其余「水墨江南」「复古胶片」不变。
2. 漫画角色一致性 spike 从 P1 **提前至 P0 第 6 周**（真实用户照片数据就绪后立即验证，见 R1）。

## 1. 里程碑总览（8 周）

```
W1      W2      W3      W4      W5      W6      W7      W8
├─骨架──┼─相机──┼─→G1   ├─拍立得─┼─→G2   ├─修图──┼─→G3   ├─内测─┼─→G4
  spikes  引导层   │      完成     │      全流程   │      验收
  备案启动          │               │               │
                            漫画一致性 spike (W6) ──┘
```

| 里程碑 | 时间 | 退出条件（Gate） | 未过怎么办 |
|--------|------|------------------|-----------|
| **G1 拍摄可用** | W3 末 | 中端目标机（红米 Note 档/荣耀数字档）取景器稳定 60fps；三分网格+水平仪+黄金时刻可用 | 降帧率至 30fps 保引导功能，图形优化移入 W7 |
| **G2 即时满足** | W5 末 | 拍立得全流程**飞行模式可用**；生图 512px 预览 P50 ≤ 15s（网关侧埋点） | 拍立得不可让步；预览时延超标则启用国内降级 Provider |
| **G3 全流程** | W7 末 | 主题修图端到端走通；首生成成功率 ≥ 90%；崩溃率 < 0.3%；AI 标识合规项全勾 | 成功率不达标冻结新主题包，专修 prompt/重试链路 |
| **G4 内测决策** | W8 末 | 内测 20–50 人，激活-次留 ≥ 30%，拍立得人均使用 ≥ 3 次 | 未达标回炉核心循环，**P1 漫画投入暂缓** |

## 2. 任务分解（WBS）

估算单位：人日。括号内为依赖。

### A. 基础设施（后端/AI 工程师主导，W1–W5）

| 任务 | 内容 | 估算 | 依赖 |
|------|------|------|------|
| A1 | Flutter 工程骨架：dev/staging/prod 三 flavor、CI（lint+test+构建）、代码规约 | 3 | — |
| A2 | 设计系统组件库：色板/字体/圆角卡片、胶片齿纹进度条、显影动画组件、快门动效 | 4 | A1 |
| A3 | **生图网关 v1**：API key 管控、设备级配额、512/1024 编辑端点、Provider 路由表（gpt-image-2 + 国内降级）、成本埋点 | 6 | — |
| A4 | 客户端网络层 + **持久化任务队列**：离线入队、退避重试、去重（内容 hash 作幂等键）、回网续跑+通知 | 5 | A3 |
| A5 | 埋点体系 + 崩溃上报（Sentry self-host 或 Bugly）：生成成功率/时延/成本三张核心报表 | 3 | A1 |
| A6 | 内容安全对接：输入 prompt 审核 + 输出图像机审（接云厂商内容安全 API） | 3 | A3 |

### B. 拍摄引导（客户端 1 号：相机/图形向，W1–W6）

| 任务 | 内容 | 估算 | 依赖 |
|------|------|------|------|
| B1 | **相机 spike（W1）**：自定义预览层（Texture+Overlay）60fps 验证，覆盖 5 台目标机清单 | 3 | — |
| B2 | 自定义取景器正式实现：点击对焦、变焦、闪光、前后摄切换 | 5 | B1 |
| B3 | 构图网格 + 电子水平仪（传感器）：三分/黄金螺旋两套，倾斜告警 | 3 | B2 |
| B4 | **ML Kit spike（W1）**：image labeling 场景识别 + pose detection 在目标机的时延/发热实测 | 2 | — |
| B5 | 场景识别 + 构图模板推送：内置 8 场景（湖泊/山野/老街/夜景/海滩/人像/美食/室内），每场景 2–3 套构图模板 | 5 | B4 |
| B6 | 黄金时刻：本地天文计算（日出日落/晨昏蒙影），倒计时提醒，纯离线 | 2 | — |
| B7 | 拍摄数据回流：引导曝光量与成片率关联埋点（P1 漫画选片也用它） | 2 | A5 |

### C. 拍立得（客户端 2 号：业务/UI 向，W3–W6）

| 任务 | 内容 | 估算 | 依赖 |
|------|------|------|------|
| C1 | 拍立得合成引擎：白框排版、胶片颗粒（FragmentShader）、三种偏色曲线参数化（600/SX-70/宽幅） | 5 | A2 |
| C2 | 显影动画：10s 渐现曲线（亮度/对比度/饱和度三通道插值），可跳过；快门黑框闪动 + haptic | 3 | C1 |
| C3 | 日期戳 + 手写体注记：本地日记句模板库 v0（按场景分类 100 句），字体方案确认 | 3 | C1 |
| C4 | 拍立得相册与照片墙：Isar→Drift 存储、墙的模板 3 套、图片导出（微信/小红书尺寸预设） | 4 | C1, A1 |
| C5 | 即时取景模式：取景器内直接套白框预览（所见即所得拍摄） | 3 | B2, C1 |

### D. 主题修图（后端/AI + 客户端 1 号联做，W4–W7）

| 任务 | 内容 | 估算 | 依赖 |
|------|------|------|------|
| D1 | Prompt 模板引擎 v1：模板 schema（风格要素/负面项/强度映射/版本号）、按主题包版本化、A/B 埋点 | 4 | A3 |
| D2 | 主题包内容格式定稿 + **首发 3 包制作**（夏日手绘动画风/水墨江南/复古胶片）：每包 ≥ 20 张实测调参记录 | 5 | D1, 设计×0.5 |
| D3 | 两段式生成流程 UI：风格轮播 → 强度滑杆 → 512 预览 → 满意后 1024 成品 → 存相册 | 5 | A4, D1 |
| D4 | 强度参数映射与一致性保障：strength→重绘幅度策略实测；构图/主体保持的 prompt 锁定语句定稿 | 3 | D2 |
| D5 | AI 生成内容标识：成品图显式角标（可关）+ 元数据声明字段，出街分享链路全覆盖 | 2 | D3, E3 |

### E. 数据、合规与运营（PM/合规 ×0.5 主导，W1 启动持续走）

| 任务 | 内容 | 估算 | 依赖 |
|------|------|------|------|
| E1 | **深度合成/生成式算法备案启动（W1）**：材料准备、主体确认、提交；跟进周期 4–8 周 | 持续 | — |
| E2 | 隐私政策与 consent 流程：人像编辑同意提示、云端处理授权、阅后即焚选项 | 3 | — |
| E3 | 免登录起步方案：设备维度配额（匿名可玩）+ 一键登录（手机号）保底 | 3 | — |
| E4 | 软著申请 + 应用商店材料（截图/说明/审核要点：AI 功能说明） | 2 | A1 |
| E5 | 成本模型表：单用户月成本测算（预览:成品 = 5:1 假设）、配额阈值反推 | 2 | A3 |

**总量**：约 92 人日（双客户端 + 1 后端并行度下 = 8 周日历周期，含 15% 缓冲）。

## 3. 风险登记簿（落地视角新增/细化）

| # | 风险 | 等级 | 对策 | 负责 |
|---|------|------|------|------|
| R1 | **漫画角色一致性不达标**（P1 最大技术风险） | 高 | W6 用内测者真实照片做 50 组 spike：参考图链+固定种子+人脸锁定，通过率 < 60% 则 P1 降级为「单格漫画化」而非连续叙事 | 后端/AI |
| R2 | 算法备案周期超预期 | 高 | W1 启动；降级预案：默认 Provider 切已备案国内模型，gpt-image-2 转为「增强通道」；内测期不依赖商店分发（TestFlight/内测包） | PM |
| R3 | 生图时延/可达性波动 | 中 | 网关双路由 + P95 监控告警；> 30s 自动切降级 Provider | 后端/AI |
| R4 | 安卓相机碎片化 | 中 | W1 spike 锁 5 台目标机（含华为/荣耀，无 GMS 机型必测）；camera plugin 不满足时备选 NativeBinder 方案评估 | 客户端 1 |
| R5 | 主题包 IP/版权 | 中 | 命名与风格描述全部去 IP 化（D2 前置修正）；风格要素写成技法描述而非「像某某」 | PM+设计 |
| R6 | 生图成本超模型 | 中 | E5 成本表 W5 评审；配额硬上限 + 高峰降级队列；单设备日生成数上限 | 后端/AI |
| R7 | 团队只有最小配置（2 人） | — | 砍 C5 与 B7，A3 网关用托管服务起步，周期 8→11 周 | — |

## 4. P1 展望与衔接（不展开，只锁定衔接点）

- 漫画：R1 spike 结论直接决定 P1 的漫画方案（连续叙事 vs 单格漫画化），**P0 不写漫画业务代码**。
- 姿势卡：B4 pose detection spike 数据留档，P1 直接进入实现。
- 照片墙导出的分享链路埋点（C4）在 P0 就埋，P1 的社交传播分析依赖它。
