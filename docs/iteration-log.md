## 设计内取舍

已知、但**不在原型里修**的条目（正式版或平台层面解决）。

| # | 问题 | 影响 | 为什么这样定 |
|---|------|------|--------------|
| K3 | AI 直连受目标服务 CORS 限制（OpenAI 官方端点可用、部分兼容网关不行） | 部分 Key 无法体验 AI 重绘 | 设计内取舍：正式版走自建网关（p0-plan 决策 D1）；原型保持浏览器直连 + 明确报错 |
| K6 | 场景识别是手动选场景 | 引导体验打折 | 设计内取舍：正式版才做 ML Kit 自动识别 |
| K9 | 生成中刷新页面 → 该任务重新排队，服务端可能已经出了一张图，属于重复生成（多花钱） | 极端情况多花一次生图费用 | 已接受：正式版用内容 hash 做幂等键（p0-plan A4）；原型接受 |
| K10 | 大量快速重渲染时，被提前 revoke 的缩略图会产生 `net::ERR_FILE_NOT_FOUND` 控制台噪声（实测 0 次元素仍在 DOM 的加载失败，纯噪声） | 仅控制台噪声 | 已接受：若以后觉得吵，改成延迟 ~1s 回收旧批次 |
| K11 | 用户显式保存过自定义 Base 时不会被覆盖（含自建网关）；保存值**恰好等于旧默认** `https://api.openai.com/v1` 的浏览器会被切到新默认（无法区分「随手沿用默认」与「手打 openai」） | 想故意继续用 openai 官方地址的人需在设置里重填一次 | 预期行为（不覆盖用户显式配置）；若需要统一，后续加「重置为默认」按钮 |
| K16 | 浏览器标签页下 iOS 不支持 Notification / Web Push（需先「加到主屏」为 standalone 才可能出现）；屏幕方向锁定、震动 iOS 一直不提供 | 想推送提醒/锁屏体验会失望 | 平台事实；需要时先把页面加到主屏再复测（`tools/ios-probe.html` 可直接重跑）；推送不是当前必需 |
| K26 | 「无缝融合」不是真无缝：它是客户端拼图时**不留缝 + 叠柔化渐变**，接缝的连续性靠后续 AI 润色兜，效果有上限 | 想要「浑然一体」的大图会不如预期 | 设计内取舍：真无缝要模型侧支持多图入参。代码里留了单一开关 `MULTI_IMAGE_EDITS_SUPPORTED`（`domain/collage.ts`），网关支持后改这一处即可走多图直传 |
| K27 | 设置是底部抽屉（设计稿里它是第 6 个 tab 的独立页面） | 设置不是「页面」而是「面板」 | 设计内取舍：两份设置表单会出现重复 id（`#aiBase` 等）与双份维护，而验收脚本按 id 取元素；tab 里的「设置」直接打开同一个抽屉，功能与字段完全一致 |
| K28 | 主题产出的参数（强度/布局/提示词）只能在「新建」面板里定；「再来一版」沿用原参数，详情面板里不能改 | 想微调参数要「复用提示词」重开一个面板 | 设计内取舍：主题可复用、可再来一版已经够用；参数编辑等有了调参数据再加（避免主题表结构过早复杂化） |
| K29 | 取景器的构图提示是**单行**且 3.5 s 自动淡出（v0.9 按用户要求改的），窄屏上较长的场景提示会被省略号截断 | 3/8 个场景的提示在 390px 宽下看不全 | 设计内取舍：常驻大卡会挡住构图，用户明确要求「单行 + 自动淡出」；完整文案放在相机抽屉的「场景相机」下方（`#hintFull`），点取景画面可再显示单行提示 |

### v0.10 · 相机取图方式可见 + 降级不再锁死（真拍照 / 抓帧一眼可见）— 2026-09-23
- 做：修一个**真缺陷** —— 以前 `takePhoto` 失败一次就把 `still` 永久置 false，整个会话后面每张都静默变成抓帧，用户无从察觉画质掉了；现在**每张都先试 `takePhoto`**，单次失败只回落**本次**，**连续失败 3 次**（`STILL_FAIL_LIMIT`，可配置）才标记「仅抓帧」，并在降级那一刻用 **toast 明确告知一次**（指路「重新检测」），成功一次即把计数归零。可见性：取景页左下角小字加**取图方式标记**（`真拍照` 金 / `抓帧` 橙警示），相机抽屉新增**「相机诊断」区**（`#camDiag`：ImageCapture 存在性与可用性 / 最近一次 takePhoto 的结果与耗时 ms / 实际分辨率 `getSettings()` / 当前取图方式 / 连续失败 n/3）与**「重新检测」**按钮（重置降级状态并当场再试一次 takePhoto）。
- 数字：快门点击同步返回 **0.1–1.1 ms**（不变）；真拍照落库 **320 ms**、抓帧回落 **331 ms**、降级后只抓帧 **23 ms**（不再白等 300 ms 的失败）；诊断区实测 `失败：setPhotoOptions failed · 16 ms` / `相机 640×480` / `3/3`；stub 修好后点「重新检测」→ `成功 · 12345 字节 · 301 ms` 且标记回到「真拍照」。
- 验：**162 单测**（相机取图 16 → 29）· **231 e2e（6 组）** · **136 guard** 全绿（`npm run verify` 退出码 0）；新增 e2e 两组 [6][7]（单次失败仍可重试并恢复真拍照 / 连续 3 次才降级 + toast 一次 + 诊断区 + 重新检测）；guard 新增 24 项（源码侧 + 产物侧 + 产物运行时真 Chromium 读 `#camHudInfoShot` 与 `#camDiag`）；`git diff --stat main -- index.html` 无改动（根原型仍 v0.6）。**未验证：真机独立模式（添加到主屏）下 `takePhoto` 是否可用 —— 本次交付的是「让用户在真机上能自己看到并自证」的能力。**

### v0.8 · 主题模式（两种产出 + 边拍边收 + 并发 9）— 2026-09-22
- 做：`web/` 落地「主题模式」设计稿——主题成为一等公民（提示词拼装器 5 组 32 词 + 实时预览 + 质量提示；两种产出：**合成一张** N→1 / **统一风格** N→N；**边拍边收**：启用后快门自动收图并逐张入队）；新增六个 tab（取景·主题·胶卷·暗房·相册·设置）、暗房显影槽 3×3、相册三分组（原始/AI 归档/主题作品）；视觉换成设计稿的深底 + 琥珀金 + 内联 SVG 场景插画 + 胶片条。
- 关键约束：**并发上限 4 → 9**；**多图上限 9**（选图/全选/合成/统一/边拍边收累积全部入口，第 10 张明确拒绝）；**一个主题任务只占 1 个槽位**（内部 2–9 张，槽位显示 `k/n`）；主题记录存独立库 `snapsaga_themes`（**不升 `snapsaga` 版本**，根原型仍读得懂）。
